# 第 1 章：机器人 Agent 由什么组成

第一次使用终端或 Python？先完成 [新手准备页](../start.html) 的小程序，再回来继续本章。

你在展厅里看到机械臂抓起积木、移动到容器上方、松开夹爪。动作很连贯，但仅凭录像，我们还不知道下一步是预先写好的，还是模型根据新画面临时决定的。课程的第一项能力，就是沿着一次操作找出每个决定的来源。

这里的 Agent 指围绕目标反复“观察、选择动作、接收结果”的系统。语言模型可以负责选择动作，但机器人还需要执行动作的工具和检查结果的方法。这门课要教的，就是怎样把这些部分接起来，并知道每一部分是否真的起了作用。

本章不要求安装环境，也不要求先写 Python。先通过观看案例、画系统结构和定义完成条件，建立后续实验需要的地图。文中的 `move()`、`grasp()` 是函数名称：可以暂时把括号理解成“请求程序执行这项操作”。

## 本章目标

学完后，你应能解释任务、观察、决策、技能、控制和验收之间的关系；能够区分固定脚本、规则闭环与在线模型决策；还能说明“机器人动了”“工具返回成功”和“任务完成”为什么是三件事。

## 从一个可检查的任务开始

我们先采用一个小任务：把红色方块移到蓝色目标区。这里至少有三个条件：操作的是指定物体、物体进入指定区域、机械臂已经释放物体。若机械臂只是夹着方块经过目标上方，不能算完成。

任务描述给出了希望发生的变化，验收函数则是一段按条件返回“满足或不满足”的程序。例如，最初可以用仿真中的方块位置判断它是否进入目标区。仿真是在计算机中计算机器人与物体怎样运动；后续本机实验都先在这个计算出来的世界里进行。

先用精确位置检查结果，能把问题缩小到动作与决策；到视觉章节再加入相机误差。写清条件，比给任务起一个宏大的名字更有用。

**先判断，再看答案。** 以下三条记录中，哪一条足以按刚才的三个条件宣布完成？

| 记录 | 已经知道的事实 | 你的判断 |
| --- | --- | --- |
| A | 机械臂到达蓝区上方，但手中没有方块 | 完成 / 未完成 |
| B | 红块到了蓝区上方，仍被夹着 | 完成 / 未完成 |
| C | 红块已经放在蓝区内，机械臂已经松开 | 完成 / 未完成 |

**对照答案：** A 缺少搬运指定物体的结果，B 缺少释放，只有 C 满足这里约定的三个条件。后续实验会进一步规定位置容差和稳定性；本章先学会从任务要求倒推要查什么证据。

## 一次操作中的六个环节

| 环节 | 输入与输出 | 需要回答的问题 |
| --- | --- | --- |
| 任务 | 人的要求 → 目标和约束 | 操作什么，放到哪里，什么叫完成？ |
| 观察 | 传感器或仿真 → 当前信息 | 现在能看到什么？信息是何时取得的？ |
| 决策 | 任务和观察 → 下一步动作 | 该找物体、移动、抓取，还是停止？ |
| 技能 | 动作及参数 → 一段执行过程 | 怎样把“到达这个位置”转换成机器人运动？ |
| 控制与仿真 | 控制目标 → 状态变化 | 关节是否真正到位，物体发生了什么变化？ |
| 验收 | 执行后的观察 → 结果 | 目标是否达成，是否需要纠正？ |

表里的“技能”可以理解成能重复调用的小操作，例如移动、抓取和释放；“控制”负责让关节实际跟上要求。一次物理仿真步只向前计算很短一段时间，上层不必每一步都重新做决定。例如，上层选择“移动到方块上方”，技能内部可以推进许多控制步后再返回结果。

机械臂装夹爪或工具的末尾叫作“末端”；让它依次经过的目标位置叫作“路点”。“接口”则约定一个操作叫什么、接收什么参数、返回什么结果。把这些约定写清楚，才能分别检查任务理解、动作参数和控制误差。

把表串成一个小片段：观察报告“工具已经靠近红块，尚未持物”；决策选择 `grasp()`；技能执行抓取；新观察报告“已经持物”；验收发现它还没进蓝区，于是循环继续。你不需要一次想完整条轨迹，先回答“现在知道什么，因此下一步做什么”。如果新观察仍是“未持物”，下一步也应重新考虑。

但分层不是一条固定规定。有的系统输出技能名称，有的输出末端路点，有的生成一段程序，有的直接输出动作序列。阅读一个项目时，先找到它的动作接口，再讨论模型“控制了什么”。

## 三种会动的系统

固定脚本按预设顺序调用动作。只要场景与假设一致，它就可能很好用；若方块换了位置，旧坐标可能失效。

规则闭环在动作之间检查状态。例如，没抓住就重新靠近。“闭环”中的环，是动作结果会返回下一次决策：观察 → 动作 → 新观察 → 再决定。它能够纠错，但下一步由人写的规则决定，不能因此称为在线大模型 Agent。

在线模型决策把当前观察交给模型，由模型选择下一步，再将执行结果返回模型。模型调用、输入、动作和反馈应该能够在日志里追踪。一次模型生成后反复执行的固定程序，也要与每步重新调用模型区别记录。

课程默认实验先提供确定性的脚本或规则示范：给定相同输入与状态，规则会选择相同操作，因此不需要模型密钥就能运行。第 6 章会在这些可用工具上搭建离线决策循环，第 7 章末再提供在线模型接入的选学步骤。

## 动手任务：给系统画一张责任图

新建一份自己的学习笔记，写下“红色方块进入蓝色目标区”的任务，并完成以下工作：

1. 画出“任务 → 观察 → 决策 → 技能 → 执行 → 新观察”的循环，把验收放在适当位置。
2. 为每个环节写一个可能的错误：认错物体、坐标用错、抓空、提前宣布完成等。
3. 为每个错误选择要检查的证据。识别错误看输入画面和对象判断；控制错误看目标与实际状态；提前停止看终止前的检查结果。
4. 给目标移动案例标注模型的输入、动作接口和已有材料能够证明的范围；有余力再对照代码单元案例。

验收时，你应能用一句话说明每个模块的责任，并且能回答：如果完全去掉语言模型，系统中哪些部分仍然有用？答案应该包括仿真环境、技能、状态记录和任务验收。

## 常见误解

“看见机械臂完成一次任务，所以系统很可靠”忽略了失败尝试和初始条件。课程后面会要求保存所有指定测试的结果。

“模型说完成了，所以完成了”把系统的判断当成了外部事实。终止前应有可检查的证据。

“技能越复杂越先进”也不成立。复杂技能可能把感知和恢复藏在内部。选择什么粒度，要看我们希望学习和比较哪一层。

## 练习

基础题：把任务改成“把两个方块按颜色分类”，补充三个新的验收条件。挑战题：设计一个录像看起来成功、实际不符合任务条件的例子，并说明哪项观测能揭示它。

基础题的一组参考答案是：两个指定方块都处理过；每个方块位于与自身颜色对应的区域；两个方块都已释放。不能只检查“目标区里有两个东西”，否则把同一个物体重复计数、或放错颜色，也可能漏检。进入下一章前，试着不看正文，用这三个条件解释为什么录像之外还要保存状态记录。
