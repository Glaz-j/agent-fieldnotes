# 第 3 章：观察与状态——机器人到底知道什么

你已经能启动场景并读取输出。现在要解决一个会影响全部实验的问题：程序拿到了方块的坐标，是否就意味着机器人“看见了”方块？答案取决于坐标从哪里来。直接读取仿真内部数据，与从图像中估计位置，是两种不同的实验条件。

前置要求是完成第 2 章，能运行 `observe` 与 `baseline`，并能阅读 JSON。你不需要先训练视觉模型。

## 本章目标

建立一份观察字段表，区分仿真状态、机器人自身反馈与相机感知；解释同一个状态为何能生成不同观察；从日志中找到动作前后的证据，并说明当前实验能够支持哪些结论。

## 状态是世界，观察是接口

仿真器为了计算运动，需要保存关节位置、速度、物体姿态等信息。这些内部状态并不自动属于 Agent。观察接口选择其中哪些内容可以交给决策程序，也可以先经过相机渲染、检测或其他处理。

用简单记号表示：世界在时刻 t 的状态是 `s_t`，决策程序获得的观察是 `o_t`，动作是 `a_t`。动作改变世界，而新观察描述变化后的信息。`o_t` 可以只是 `s_t` 的一部分，也可能带噪声或延迟。它不必足以完全恢复世界。

例如，只给一张 RGB 图时，遮挡后的方块仍存在于仿真状态中，却可能完全不出现在观察里。直接输出方块三维坐标则绕过了遮挡。这种为实验提供的精确信息通常称为特权状态或仿真真值。

使用真值并没有问题：它能帮助我们先隔离控制与决策错误。问题在于把这种条件下的成功，解释成视觉系统已经解决了定位。我们会在第 8 章建立相机感知路径，并明确记录输入的变化。

## 阅读课程的观察协议

在仓库根目录、已激活的虚拟环境中运行：

```sh
python lab/run.py observe
```

本阶段输出的 `observation_source` 为 `simulator_state`。这是数据来源标签，不是模型名称。重点检查下面这些字段：

| 字段 | 含义 | 本阶段的数据来源 |
| --- | --- | --- |
| `robot.joints_rad` | 转动关节角度，单位弧度 | 仿真关节状态 |
| `robot.vertical_slide_m` | 竖直滑动关节位移，单位米 | 仿真关节状态 |
| `robot.tool_xyz` | 末端在世界坐标系中的位置，单位米 | 仿真运动学结果 |
| `robot.holding` | 教学附着约束是否启用 | 仿真技能状态 |
| `scene.block_xyz` | 方块位置，单位米 | 仿真物体真值 |
| `scene.goal_xyz` | 目标区位置，单位米 | 仿真场景真值 |
| `scene.block_linear_speed_m_s` | 方块当前平移速率，单位米每秒 | 仿真速度状态 |
| `task.success` | 当前是否满足课程的任务验收 | 仿真状态判定 |

这里的 `holding` 不是现实夹爪力传感器测量，`block_xyz` 也不是检测器输出。它们准确地反映了本课程简化场景中相应的状态，但不能直接迁移成真实机器人的感知结论。

## 实验一：写一张数据来源表

将实际输出保存到学习笔记，为每个字段补充四项说明：单位、坐标系、来源、用途。先看末端与方块的三个分量，判断你能否据此计算水平距离；再看 `holding` 和 `success`，说明二者为什么不能互相代替。

假设方块已经被夹持，但仍在原地，`holding` 可以为真，任务仍未完成。再假设方块移动到目标上方却没有释放，仅有水平位置接近也不足以验收。把状态拆开，才能定位究竟是哪项条件缺失。

最后，划出你愿意提供给决策程序的字段，以及只保留给评测器的字段。本阶段实验可以公开使用真值；以后比较视觉方法时，则必须检查评测器的内部坐标有没有通过提示词或工具响应泄漏回决策程序。

## 实验二：用动作前后信息解释变化

运行一条带日志的基线：

```sh
python lab/run.py baseline --seed 7 --out runs/observation-study
```

打开目录中的 `events.jsonl`。JSONL 的每一行是一个独立 JSON 事件；按文件顺序阅读，找到抓取前、抓取后、释放后的相关记录。再打开 `summary.json`，将汇总结果与事件中的状态对照。

为三个时刻各写一句话，句子必须包含证据。例如，“附着状态由假变真”只支持教学抓取状态发生变化；要说明物体真的被带走，还需要比较后续方块位置。不要把自己的预期写成实际输出。

再找一次移动事件，记录要求到达的位置和反馈中的实际位置。这两者可能很接近，却属于不同类别：前者是命令，后者才是执行后的观察。控制误差要从它们的差值计算，不能直接把命令复制进结果表。

## 观察还包含时间含义

同一个数字在不同时间有不同价值。抓取前获得的方块位置，在方块被推动后可能已经过期；旧位置即使来自准确的真值，也不能代表现在。

课程日志中的 `step` 和 `sim_time_s` 分别记录事件编号与仿真时间，能帮助追踪先后关系。做笔记时保留它们和对应动作，不要只摘出一个孤立坐标。仿真时间不等于现实等待时间；将来接入异步相机与模型时，还要记录采集时间与处理时间，慢的推理可能让“刚收到”的结果对应较早画面。

另外，读取底层数组时要区分引用与快照。MuJoCo 的运行数据会随仿真更新；保存一个仍指向同一数组的引用，不一定保存了过去。本课程的 JSON 记录用于留下具体数值，自己扩展日志时也应在记录时复制需要的数据。

## 案例阅读：记忆能否代替新观察

阅读 [MemS 视觉空间记忆案例](../gallery.html#demo-mems-visual-memory-libero-three)，再对照 [目标移动案例](../gallery.html#demo-mems-target-shift-libero-three)。这两项是现有展厅材料，不是本章实验包的完整复现。

记录系统记住了什么，以及环境变化后哪些记忆需要更新。记忆可以减少重复推理，但不能保证环境保持不变。评估记忆的价值，应同时看它帮助了哪些决策，以及错误记忆是否能被新证据修正。

## 验收、常见错误与练习

验收产物是一张数据来源表和三段带事件证据的状态解释。你应能明确说出：当前控制实验使用仿真真值，尚未证明相机定位能力；任务成功需要多项条件，工具返回值只覆盖其中一部分。

常见错误包括把坐标叫作“视觉识别结果”、把动作目标当成实际位置、把旧观察当成当前状态，以及把评测器知道的所有信息都交给 Agent。遇到不确定字段，先查生成它的代码，不要从名字猜测来源。

基础题：只保留末端位置和夹持状态，决策程序还缺少什么才能定位方块？挑战题：设计一张遮挡场景图，列出仿真真值、RGB 观察和历史记忆三者各自能提供的信息，并指出仍然无法确定的内容。
