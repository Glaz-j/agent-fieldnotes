# 第 13 章：用受限程序组织机器人计划

逐步选择动作容易理解，但“尝试抓取，确认抓住后再搬运”本身就包含重复和条件。把这些关系写成程序，可以让一次计划包含多个技能，并把局部检查留在执行过程中。本章用一个小型 JSON 语言完成这件事。

前置要求是熟悉第 5 章技能、第 9 章恢复，以及任务记忆与空间信息的时效性。你需要会读列表和字典，不需要编译器知识。实验仍采用单方块 SCARA、仿真状态观察与教学附着抓取，没有调用语言模型。

## 本章目标

读懂并运行一段带分支和重复的搬运计划，解释执行时的坐标引用，检查节点预算，并让一个不合法计划在执行前被拒绝。你要交付计划文件、运行记录和一次预算不足的分析。

## 为什么把计划写成一门小语言

普通动作列表只能表达先后顺序。加入条件以后，程序可以表达“已经抓住才运输”；加入有限重复，可以表达“最多尝试三次”。这两项能力已经足够展示程序化策略的重要思想：行动由状态与控制结构共同决定。

课程解释器只认识预先定义的语法，不执行 Python 字符串。JSON 在这里负责保存结构，解释器负责赋予结构含义。一个 JSON 能成功读取，并不意味着它是合法计划；合法计划也不保证任务成功。这三层需要分别检查。

Code as Policies 研究了模型生成程序、组合感知与控制接口的路线。本章把重点放在可审阅的执行机制，计划由人编写，不把示例文件称为模型生成结果。[原始项目与论文](https://code-as-policies.github.io/)

## 第一步：认识三个节点

顶层使用 `version` 和 `steps`。`steps` 中的节点只有三类：

| 节点 | 写法 | 作用 |
| --- | --- | --- |
| 技能调用 | `{"call":"grasp"}` | 调用一个允许的工具 |
| 条件分支 | `{"if":"holding","then":[...]}` | 条件成立才执行分支，可附加 `else` |
| 有限重复 | `{"repeat":3,"steps":[...]}` | 重复执行指定节点列表 |

允许的工具是 `observe`、`move`、`grasp`、`release`。条件包括 `holding`、`not_holding`、`success`、`not_success`、`last_ok`。前四项查询当前状态，`last_ok` 查看上一个工具返回结果。条件名称是解释器定义的枚举，不是任意 Python 表达式。

`move` 的参数可以是数值，也可以是 `block.x`、`block.y`、`goal.x`、`goal.y`、`tool.x`、`tool.y` 这样的引用。引用在执行该动作时解析，因此 `goal.x` 表示此刻目标位置，而非生成计划时缓存的坐标。它仍然读取仿真真值，不是从文字推测位置。

## 第二步：逐行解释一个完整计划

在已激活环境、包含 `lab/` 的目录运行：

```sh
python -m json.tool lab/example-program.json
```

示例先移动到方块上方，再下降。抓取部分是下面的结构：

```json
{
  "repeat": 3,
  "steps": [
    {"if": "not_holding", "then": [{"call": "grasp"}]}
  ]
}
```

注意，重复三次并不意味着总会调用三次 `grasp`。第一次成功后，后续两次条件为假，不再抓取。这是程序结构执行次数与机器人动作次数不同的一个具体例子。

搬运部分放在 `holding` 分支中：先用当前工具的水平坐标抬升，再移动到当前目标上方，下降并释放。这样，三次都抓不到时，不会继续执行“空手搬运”。最后的观察用于检查状态，不能替代任务验收函数。

画一条分支路径：第一次抓取失败、第二次成功时，哪些节点被访问，哪些动作真正执行？先写预测，再阅读运行记录。

## 第三步：执行同一个计划

```sh
python lab/advanced.py program --program lab/example-program.json --budget 64 --seed 7 --perturb none --out runs/ch13-program
```

程序会先检查整份计划，再执行节点。`program.json` 保存实际计划，`events.jsonl` 保存工具事件，`summary.json` 提供 `executed_nodes`、`tool_calls`、`budget`、`error` 和 `success`。发布前 seed 7 的无扰动实跑访问 13 个节点、执行 8 次工具调用并完成任务。先将记录与预测对应起来，再故意让第一次抓取失败：

```sh
python lab/advanced.py program --program lab/example-program.json --budget 64 --seed 7 --perturb miss-grasp --out runs/ch13-retry
```

本次需要通过 `not_holding` 分支再次抓取。恢复由你写入的重复与条件产生，不是解释器自动理解了任务。如果计划只写一次 `grasp`，解释器不会擅自补上重试。

再运行目标移动条件：

```sh
python lab/advanced.py program --program lab/example-program.json --budget 64 --seed 7 --perturb shift-goal --out runs/ch13-current-goal
```

对照抓取后的目标变化与后续 `move` 参数，检查动态引用是否采用新坐标。这个对照说明：程序可以预先写好，而其中的动作参数仍然在执行时根据新状态确定。

## 第四步：理解结构上限与运行预算

解释器限制最大嵌套深度、节点总数和单个重复次数，当前分别为 6、128 和 16。运行时另设节点预算；调用、条件和重复节点都会消耗预算，防止“没有机器人动作的循环”绕过限制。

```sh
python lab/advanced.py program --program lab/example-program.json --budget 1 --seed 7 --out runs/ch13-budget
```

这次预算不足是预期实验。逐条运行命令，保留失败结果，不要求整批命令都以零退出码结束。注意预算耗尽可能发生在部分动作已经执行以后：它限制工作量，不会把物理场景回滚到开始。

节点预算也不是仿真步数或耗时。一次 `move` 内部推进许多物理步，一次条件判断却不移动机器人。报告开销时分别记录节点访问与实际工具事件，不要把二者混成同一个“步”。

可以手算一个例子：外层重复 4 次，内部再重复 4 次，每次只调用一次 `observe`。语法树只有外层重复、内层重复和观察三个节点，但运行时会访问外层 1 次、内层 4 次、观察 16 次，共消耗 21 个节点单位。静态节点数限制文件复杂度，动态预算限制实际执行量，两者解决不同问题。

条件也不会自动停止整份计划。某个 `then` 分支执行完后，解释器继续处理它后面的节点。如果希望抓取失败后不搬运，就要把整段搬运放进 `holding` 分支，而不是只给第一条移动加条件。画出语法树，比仅凭缩进感觉理解执行顺序更可靠。

## 第五步：自己写一个可检查的计划

用编辑器将下列内容保存为 `invalid-program.json`，不要加入 JSON 注释：

```json
{"version": 1, "steps": [{"call": "teleport"}]}
```

```sh
python lab/advanced.py program --program invalid-program.json --budget 64 --seed 7 --out runs/ch13-invalid
```

`teleport` 不在允许列表中，应在计划执行前被拒绝。将错误工具藏在一个当前不会进入的分支，仍应被发现，因为校验覆盖整棵语法树。这里检验的是语法与接口边界，不能推导出合法动作一定可达。

接着复制示例计划，尝试用 `last_ok` 限制失败动作后的继续执行。设计时明确哪个工具的结果正在被检查：插入一个 `observe` 会更新“上一个结果”，不应再把它误当成此前移动的结果。

## 本章验收与排查

解释默认运行、抓空恢复、目标移动、预算不足和非法工具五种结果。成功运行要指出抓取与释放证据，失败运行要说明属于校验、预算还是技能执行。不要只提交最后一个布尔值。

如果 JSON 读取失败，先检查引号和逗号；如果语法通过却任务失败，检查条件是否放错位置、引用是否对应正确实体，以及动作返回。把任何失败都归给“计划不好”，会掩盖具体错误。

本章命令没有依赖 shell 的 heredoc，macOS、Linux 与 PowerShell 均可按普通命令运行；JSON 文件使用编辑器保存为 UTF-8。若自行写多行 Python 检查程序，在 PowerShell 中将其保存为 `.py` 文件后运行。
