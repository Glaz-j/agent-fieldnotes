# 第 15 章：用匹配实验判断系统究竟改进了什么

一个方法完成任务，另一个方法失败，还不足以说明前者更好：它们可能遇到了不同初始位置、使用了不同观察，或者拥有不同预算。本章将比较条件固定下来，通过配对种子与消融，定位恢复能力来自哪个机制。

前置要求是理解第 9 章扰动、第 10—11 章记忆，以及技能日志。本实验使用确定性控制器；随机种子改变场景初始化，不是语言模型采样种子，也不是训练神经网络的种子。

## 本章目标

完成 60 回合的四策略对照，验证初始条件匹配，从原始事件解释失败，并报告样本量限制。最终交付全部回合、分组表和两个机制归因，不只挑选成功案例。

## 第一步：先定义要回答的问题

本章有两个具体问题：抓空后重试是否帮助恢复？目标移动后重新读取位置是否必要？为了回答它们，比较四种策略：

| 策略 | 重试 | 目标位置 | 用途 |
| --- | --- | --- | --- |
| `baseline` | 忽略返回、继续固定序列 | 初始缓存 | 固定脚本参照 |
| `feedback` | 根据反馈继续 | 每轮更新 | 完整反馈控制 |
| `no-retry` | 第一次工具失败后停止 | 每轮更新 | 去除失败后继续尝试 |
| `stale-spatial` | 保留 | 始终复用初始缓存 | 去除目标刷新 |

固定基线与完整反馈有多处差异，二者对比只能说明整体流程不同。后两项从反馈控制器中分别移除一个机制，才更接近回答“哪一项起了作用”。消融是控制变量的实验设计，不只是给同一程序换个名称。

## 第二步：运行预先确定的矩阵

在已激活环境、包含 `lab/` 的目录执行：

```sh
python lab/advanced.py benchmark --seeds 5 --out runs/ch15-benchmark
python -m json.tool runs/ch15-benchmark/summary.json
```

`--seeds 5` 表示种子 0 到 4。每个种子分别测试无扰动、一次抓空、一次目标移动，再运行四种策略，共 `5×3×4=60` 回合。这里使用的是 `--seeds`，单数 `--seed` 不负责指定这个评估矩阵。

`summary.json` 保存分组成功数与平均工具调用数；`episodes.json` 保存每个回合的初始、最终观察；`events.jsonl` 在每条工具事件上附加种子、扰动和策略，便于回到具体失败。

运行结束不代表所有回合成功。评估程序的职责是完成测试矩阵，预期失败也必须进入结果。不要因失败删掉回合，或让一个非零结果使后续策略没有机会执行。

## 第三步：验证配对，而不是只相信种子相同

相同种子只有在相同初始化程序、参数与版本下才有比较意义。本实验为每个策略创建新世界，并保存 `initial_observation`。将下面的完整程序保存为 `check_pairs.py`，运行 `python check_pairs.py`；macOS、Linux 与 PowerShell 都可采用此方式。

```python
import json
from pathlib import Path

rows = json.loads(Path("runs/ch15-benchmark/episodes.json").read_text())
policies = ("baseline", "feedback", "no-retry", "stale-spatial")
conditions = ("none", "miss-grasp", "shift-goal")
index = {(r["seed"], r["perturb"], r["policy"]): r for r in rows}
assert len(rows) == len(index) == 60
for seed in range(5):
    for condition in conditions:
        group = [index[seed, condition, p] for p in policies]
        first = group[0]["initial_observation"]
        assert all(r["initial_observation"] == first for r in group)
for condition in conditions:
    for other in ("no-retry", "stale-spatial"):
        win = loss = tie = 0
        for seed in range(5):
            a = index[seed, condition, "feedback"]["success"]
            b = index[seed, condition, other]["success"]
            win += int(a and not b)
            loss += int(b and not a)
            tie += int(a == b)
        print(condition, other, "完整反馈胜/负/平：", win, loss, tie)
```

这段程序检查矩阵是否缺回合、是否存在重复键，以及配对初始状态是否一致。它不检查全部实验公平性；机器人模型、观察权限、终止规则等仍需要从实现与配置核对。

## 第四步：读懂真实结果

发布前实际运行的五个种子得到下面的成功数。请将你的结果与原始文件对照，而不是把这张表当作要手工填出的答案。

| 策略 | 无扰动 | 一次抓空 | 一次目标移动 |
| --- | --- | --- | --- |
| 固定基线 | 5 / 5 | 0 / 5 | 0 / 5 |
| 完整反馈 | 5 / 5 | 5 / 5 | 5 / 5 |
| 去除重试 | 5 / 5 | 0 / 5 | 5 / 5 |
| 陈旧目标位置 | 5 / 5 | 5 / 5 | 0 / 5 |

去除重试只在抓空条件下出现差异，支持“恢复该故障需要失败后继续尝试”的解释。陈旧目标只在目标移动条件下出现差异，支持“动作参数需要更新”的解释。这些归因限于本实验注入的故障，不是对所有抓取失败和动态场景的定理。

再看开销：抓空条件下完整反馈平均调用 8 次工具，去除重试只调用 3 次，但后者任务失败。目标移动下陈旧位置策略用满 32 次工具仍失败，完整反馈为 7 次。单独说“调用更少”或“行动更多”都不能代表效果更好。

当前评估日志没有显式的 `termination_reason` 字段。“用满预算”的判断来自未成功、32 次工具调用，以及源码中控制循环上限三项证据，属于据此作出的解释。报告时不要把这个解释伪装成日志里已经提供的字段。

## 第五步：从事件做失败归因

挑一个失败回合，在 `events.jsonl` 中按 `seed`、`perturb`、`policy` 筛选。先找第一处异常，再看它是否被后续状态纠正，最后查看独立任务验收。

抓空通常有显式错误 `injected_miss_grasp`；目标陈旧却可能每次移动都返回成功，因为机器人确实到了错误的旧位置。后一类失败应归因于使用了过期目标，而不能算成运动控制未到位。

记录中还应区分接口错误、技能失败、目标关系不满足与预算耗尽。对一个回合可以保留多个证据，但不要把每条失败工具事件都算成一次独立任务失败，否则失败率的分母会混乱。

## 先定义分母，再计算指标

任务成功率的分母是指定条件下的回合数；工具错误比例的分母是工具事件数；重试恢复比例的分母则应是实际遭遇目标故障的回合。三者回答不同问题，不能互相替换。本实验的 `mean_tool_calls` 使用该分组全部回合，包括提前停止与用满预算的失败。

如果只统计成功回合的调用开销，也可以得到有用信息，但必须标明筛选条件，同时报告被排除的失败数量。一个只完成最容易任务的策略，成功回合可能非常短，这不表示它整体更高效。

分析结果后可以提出新假设，但不要在同一批种子上反复改规则，直到全部通过，再将它们称为未见测试集。保留用于开发的种子，另定一批最终评估种子；如新增故障类型，也先规定注入时机和强度。第 14 章的训练与测试分离，在这里对应的是方案调整与最终比较之间的分离。

## 为什么 5 / 5 不能叫“稳定百分之百”

五个初始化样本只覆盖一个很窄的范围。同一个确定性种子重复运行五次，可以检查复现性，却不会变成五个新的独立场景。三种扰动各自五次，也不能合并成“每个条件有十五个样本”。

即使采用独立同分布伯努利样本的理想假设，5 次全成功的 95% Wilson 区间下界也只有约 0.566。这里用它说明小样本的不确定性，不把该区间解释成真实机器人的可靠性承诺。区间所依据的目标分布必须先定义，不能用统计公式弥补没有代表性的任务集合。[NIST 比例区间说明](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)

强化学习评估研究也指出，仅比较少量运行的点估计，可能得到与考虑不确定性后不同的结论。本章没有复现其算法评测，而是采用保留回合和说明样本量的基本原则。[原论文](https://arxiv.org/abs/2108.13264)
