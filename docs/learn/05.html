把动作封装成技能

为移动、抓取与放置定义可检查的接口

如果每次决策都要重新处理关节角、执行步数和附着状态，最小任务也会迅速变得混乱。技能接口把常用操作组织成明确的输入、执行过程与反馈，让上层能够选择动作，也能够知道动作为什么失败。

前置要求是完成第 4 章，理解世界坐标、可达性以及目标和实际位置的区别。你将继续使用同一个 SCARA 场景，不需要模型密钥。

本章目标

读懂课程的四个基础技能，为每个技能写清前置条件和执行后检查；从一次基线日志还原完整操作；区分工具成功、物体状态变化和任务成功，并识别一个忽略失败反馈的执行器。

技能不是只有一个函数名字

grasp() 看起来没有参数，但它并不在任何时刻都能成功：机器人需要靠近方块，而且不能已经持有物体。一个有用的技能协议至少包括以下内容。

输入规定参数、单位和坐标系；前置条件规定当前是否适合执行；执行过程规定内部做什么；返回值报告结果和原因；执行后检查确认承诺是否兑现。不要把所有失败都压成一个“出错了”，否则上层无法区分需要重新定位、先抬升，还是改一个不可达目标。

课程的基础接口如下：

技能 输入与关键前置条件 返回后要检查什么
observe() 无动作参数 信息来源、当前末端和物体状态
move(x, y, z) 世界系米制坐标；目标可达；低处横移有限制 ok、错误原因、实际末端位置
grasp() 当前未持物；末端足够接近方块 ok 与新的 robot.holding
release() 当前持有物体 已解除附着；物体位置与任务验收

相机定位接口放到第 8 章讲解。这里先让状态输入和基础动作之间的关系完整可检查。

仔细读懂三个动作的边界

move 的 z 范围是 0.045 至 0.32 米；它先检查几何可达性，再设置关节控制目标并推进仿真。末端与请求位置的距离小于 0.02 米时报告到位。如果末端低于 0.12 米而水平目标距离超过 0.04 米，接口返回 lift_before_lateral_motion，要求先抬升。

这项规则是教学执行约束，不是完备的碰撞规划。它使“先抬升、再横移”的过程可见，但没有证明任意场景中的路径都安全无碰撞。

grasp 要求末端与方块的水平距离小于 0.035 米，垂直距离小于 0.05 米。成功时启用显式焊接约束，模拟抓住方块。这个简化让我们研究技能组合和反馈，不能用来声称真实指尖接触或摩擦抓取已经解决。

release 解除约束后继续推进仿真，让物体有时间落下。解除约束成功不意味着放置成功；若释放位置不对，方块仍可能落在目标区之外。

实验一：还原基线的七次调用

在仓库根目录执行：

python lab/run.py baseline --seed 7 --out runs/skills-baseline

打开 events.jsonl。每行包含 step、sim_time_s、tool、arguments 与 result。其中 result.observation 是该次动作后的状态，result.ok 是技能结果，失败时还有 result.error。

按顺序给七次调用写上动作意图：到方块上方、下降、抓取、抬升、到目标上方、下降、释放。不要只写“move”。同一种技能在不同阶段承担不同目的；理解意图，才能知道失败后应该返回哪个阶段。

随后检查三类证据：每次移动的目标与实际末端位置，抓取后是否持物，释放后方块是否进入目标且稳定。最后打开 summary.json，确认 mode 为 baseline、model_calls 为 0，并将 success 与最终状态对照。

当前任务验收同时检查已经释放、方块水平位置距目标中心小于 0.045 米、方块高度处于 0.015 至 0.065 米之间、平移速度小于 0.05 米每秒。因此，短暂经过目标上方与完成放置不是同一个事件。这些阈值是本课程场景的具体定义，不是所有机器人任务通用的标准。

实验二：一个工具失败以后发生什么

保持同一个种子，加入一次人为抓空扰动：

python lab/run.py baseline --seed 7 --perturb miss-grasp --out runs/skills-miss

本次实验会让第一次抓取明确返回 injected_miss_grasp。这是可重复的教学故障注入，不是在测量物理抓取的随机失效率。命令的非零退出码符合本次失败实验的目的，仍应打开日志查看全过程。

找到失败的那一行，再向后阅读。基线仍按原定顺序继续移动与释放，因为它有意忽略工具反馈。观察后续 holding 是否改变，最后是否出现 empty_gripper，并用 summary.json 的 success 给出任务结论。

这个对照揭示了一个区别：技能接口能准确报告失败，上层执行器仍可能做错。不能因为一次任务失败，就把全部责任归给感知或底层控制。第 6 章会加入读取反馈的闭环，第 9 章再比较恢复行为；本章先把问题定位清楚。

从技能调用到任务状态

可以把任务写成几个阶段：寻找目标、接近、抓取、运输、释放、验收。但阶段跳转必须有证据。调用过 grasp 不应自动进入运输阶段；应该先确认抓取结果和持物状态。调用过 release 也不应直接宣布完成；应该再检查任务条件。

同样，不能无限重试。对不可达坐标重复移动，与对一次暂时抓空重新靠近，需要不同策略。错误原因决定是否值得重试，重试预算决定何时停止并报告问题。这些规则既适用于确定性程序，也适用于下一章接入的模型决策。

案例阅读：程序封装了多少决策

打开 PyRUA-Lean 代码单元案例。尝试区分模型生成的代码、代码调用的动作和动作内部执行。若一个代码单元包含循环与条件分支，它就承担了部分局部决策；不能只按代码单元数量计算机器人实际执行了几步。

本章借案例练习接口分析，不承诺用本课程 SCARA 实验复现案例中的机器人与实验设置。

验收、常见错误与练习

提交两份实际运行记录，以及一张包含动作意图、前置条件、结果和下一步选择的表。你应能指出抓空发生在哪个事件、基线为何没有恢复，并写出下一章决策器必须遵守的一条反馈检查规则。

常见错误是把 ok 和 task.success 混为一谈，把“调用过”当成“实现了”，以及用接口名称掩盖内部假设。阅读技能源码时，尤其要找阈值、状态改变和失败分支。

基础题：为 grasp 的 already_holding 和 not_at_block 分别写出合理的后续动作。挑战题：设计“运输途中目标改变”的阶段跳转，说明必须重新读取哪项状态，以及仅复用初始目标坐标为什么会失效。
